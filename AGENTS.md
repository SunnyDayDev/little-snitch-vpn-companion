# Little Snitch VPN Companion

Menu-bar-приложение для macOS: следит, чтобы трафик не уходил мимо VPN, и при
утечке закрывает rule groups в Little Snitch. Домен — чистый Swift, Apple-фреймворки
живут в слоях выше, привилегированные операции — в helper через XPC.

## Красные линии

Нарушение любой из них означает переделку, поэтому проверяй до, а не после.

- **Никаких реальных IP-, MAC-адресов и ключей** — ни в коде, ни в доках, ни в
  тестах, ни в макетах (`design/app.pen` — обычный JSON, его тоже проверять).
  IP-примеры только из документационных диапазонов RFC 5737: `192.0.2.0/24`,
  `198.51.100.0/24`, `203.0.113.0/24` (исключения — служебные адреса вроде
  `1.1.1.1` и частные диапазоны). MAC-примеры — синтетические
  locally-administered (`02:…`). Реальные адреса VPN-инфраструктуры живут только
  в локальных настройках приложения (`defaults`), ключи и сертификаты — в Keychain.
- **`main` защищён.** Изменения попадают только через pull request с зелёным CI;
  прямые пуши и force-push запрещены даже владельцу. Обязательных проверок две —
  «Тесты (macOS 26)» и «Тесты (macOS 15)», по границам поддерживаемого диапазона.
- **Изменение логики идёт через openspec-процесс** и обновляет спеки. Код без
  обновлённых спек — неполное изменение.
- **`Domain/` — чистый Swift без Apple-фреймворков.** Проверяется
  `Scripts/check-domain-purity.sh` и в CI.
- **`.xcodeproj` не хранится в git** — он генерируется XcodeGen, а таргеты и
  настройки правятся в `project.yml`.
- **Язык:** документация, спеки и комментарии в коде — на русском; идентификаторы
  в коде — на английском.

## Где искать правду

| Где | Что |
| --- | --- |
| `openspec/specs/<capability>/spec.md` | актуальное поведение системы: требования SHALL + сценарии, по файлу на capability |
| `openspec/changes/archive/` | завершённые изменения |
| `SPEC.md` | исходное ТЗ; на его §-нумерацию ссылаются комментарии в коде («таблица §8.1»), поэтому сохраняется как справочник |
| `CONTRIBUTING.md` | процесс целиком: шаги openspec, требования к PR, работа с личными данными |
| `README.md` | сборка, установка, архитектура, собранные грабли |
| `.agents/skills/<name>/SKILL.md` | навыки агентов, включая выпуск релиза |

## Процесс изменения логики

Четыре шага, каждому соответствует навык из `.agents/skills/`; под капотом —
[OpenSpec CLI](https://openspec.dev).

1. **propose** — создать change: `proposal.md` (что и зачем), дельты спек
   `specs/<capability>/spec.md` (какие требования добавляются или меняются),
   `design.md` (как), `tasks.md` (шаги реализации).
2. **apply** — реализация по tasks. Новая логика — вместе с тестами: таблицы
   поведения `Domain/` покрываются построчно.
3. **sync** — перенести дельты в основные спеки `openspec/specs/`.
4. **archive** — после завершения переместить change в `openspec/changes/archive/`.

**Что считается изменением логики:** детектор и классификатор, state machine,
политика реакции, эскалация, контракт helper, поведение настроек, онбординга,
уведомлений и UI.

**Что можно без openspec-процесса:** опечатки, документация, CI, скрипты,
рефакторинг без изменения поведения.

## Перед пушем

```bash
xcodegen generate && xcodebuild -project LittleSnitchVPNCompanion.xcodeproj -scheme LittleSnitchVPNCompanion -configuration Debug test
```

```bash
./Scripts/check-domain-purity.sh
```

Ветка от `main` → PR → мерж после обеих зелёных проверок. Ревью не требуется,
CI обязателен; ветка должна быть актуальной относительно `main`.

## Конфигурация агентов

Этот файл — единственный источник правды, и он инструменто-независим: без
синтаксиса конкретного харнесса. Файлы вроде `CLAUDE.md` импортируют его первой
строкой и добавляют только то, что относится к своему инструменту.

Навыки лежат реальными директориями в `.agents/skills/<name>/`. Инструменто-специфичные
каталоги ссылаются на них относительными симлинками — по одному на навык,
а не одной ссылкой на каталог навыков целиком.
