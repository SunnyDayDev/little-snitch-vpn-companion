## 3. Application: координатор с N детекторами

- [ ] 3.1 `MonitoringCoordinator` держит рантаймы по `DetectorID` (машина, растяжка, цикл проб, поколение проб, последний вердикт) и общие слои; `MonitoringSnapshot.detectors` и сводное состояние; существующие тесты координатора проходят с одним детектором «Основной»
- [ ] 3.2 Общие слои: смена пути инвалидирует пробы всех и пробует каждого после одного debounce, пропажа сети гасит всех, сон и пробуждение раздаются всем, РУ-маяк подставляет прямой IP всем и зовёт guard по всем; тесты с двумя детекторами на каждое событие
- [ ] 3.3 Reconcile по арбитражу: `ApplyPolicy` принимает цель и `managed` от арбитра, `activeLeakGroups` = `enable`; тесты: утечка одного при защите другого закрывает только его группы, общая группа остаётся закрытой, «никто не определяет» не трогает, выключенный детектор не участвует
- [ ] 3.4 Пауза, возобновление, старт, завершение и сон для всех машин; `forceEnable` по объединению строгих; тесты: старт со смешанными режимами, пауза закрывает только строгие, сон при двух строгих
- [ ] 3.5 Изменения детектора на лету: режим (переходный reconcile по арбитражу с новым режимом), выключение и удаление (открыть эксклюзивные группы, предупреждение при Leak), включение (старт как при старте мониторинга), смена маяка/прокси/растяжки (перезапуск слоёв детектора и проба); тесты на каждый случай
- [ ] 3.6 Эскалация по любому детектору в Leak один раз за эпизод недоступности helper; `observeOnly` поверх всех детекторов с журналом «закрыл бы» по имени; тесты: второй детектор в Leak в том же эпизоде не эскалирует, наблюдение при двух строгих
