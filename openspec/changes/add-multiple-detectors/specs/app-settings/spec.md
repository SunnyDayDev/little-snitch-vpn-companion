# Spec Delta

## MODIFIED Requirements

### Requirement: Персистентные настройки

Настройки SHALL храниться в `UserDefaults` с ключами: `launchAtLogin`, `monitoringEnabled`, `observeOnly`, `escalationEnabled`, `notifyTransitions`, `notifyErrors`, `heartbeatSeconds`, `probeSeconds`, `probeTimeoutSeconds`, `ruBeaconURL`, `ruBeaconRefreshSeconds` и `detectors` — массив детекторов в JSON, где у каждого детектора: идентификатор, имя, признак «включён», `protectionMode` (строка `reactive`/`strict`), основной и резервный URL маяка, формат ответа маяка (`cdnCgiTrace`/`plainIP`), прокси (вид `none`/`httpConnect`/`socks5`, хост, порт), флаг «`warp=on` считается защитой», ожидаемые IP, запрещённые IP, признак «растяжка включена», список групп. Ключи `expectedIPs`, `leakGroups`, `forbiddenEgressIPs` и `protectionMode` SHALL сохраняться только как источник миграции (см. «Миграция настроек одного детектора») и после неё SHALL NOT читаться. Динамический прямой РУ-IP SHALL NOT сохраняться в defaults (runtime-значение, сбрасывается при смене сети). Нераспознанное значение режима детектора SHALL трактоваться как `reactive`; нечитаемый массив детекторов SHALL давать предупреждение в журнале и один детектор по умолчанию.

#### Scenario: Настройка переживает перезапуск

- **WHEN** пользователь изменил `probeSeconds` и перезапустил приложение
- **THEN** применяется сохранённое значение

#### Scenario: Детектор переживает перезапуск

- **WHEN** пользователь добавил детектор с SOCKS5-прокси и перезапустил приложение
- **THEN** детектор присутствует с теми же прокси, маяком, правилами и группами

#### Scenario: Прямой IP не персистится

- **WHEN** приложение перезапущено
- **THEN** динамический прямой РУ-IP отсутствует до нового ответа РУ-маяка

#### Scenario: Режим защиты переживает перезапуск

- **WHEN** пользователь включил строгий режим у детектора и перезапустил приложение
- **THEN** детектор стартует в строгом режиме (закрытие до первого вердикта)

#### Scenario: Массив детекторов повреждён

- **WHEN** значение ключа `detectors` не разбирается как JSON ожидаемой формы
- **THEN** в журнал пишется предупреждение, приложение работает с одним детектором по умолчанию, повреждённое значение не перезаписывается до первого изменения настроек пользователем

### Requirement: Значения по умолчанию

При первом запуске SHALL действовать конфигурация: `monitoringEnabled=true`, `observeOnly=false`, `escalationEnabled=true`, `launchAtLogin=true` (после онбординга), `heartbeatSeconds=15`, `probeSeconds=60`, `probeTimeoutSeconds=6`, подтверждение утечки 2 пробы / 2.5 с, обе категории уведомлений включены, `ruBeaconURL="https://yandex.ru/internet/api/v0/ip"`, `ruBeaconFallbackURL="https://2ip.ru"`, `ruBeaconRefreshSeconds=300`, и один детектор «Основной»: включён, режим `reactive`, без прокси, маяк `https://www.cloudflare.com/cdn-cgi/trace` с резервным `https://1.1.1.1/cdn-cgi/trace` формата `cdn-cgi/trace`, «`warp=on` считается защитой» включено, ожидаемые и запрещённые IP пусты, растяжка включена, группы `["VPN down"]` (если группа существует в LS; иначе пусто + подсказка в UI). Новый детектор, добавленный пользователем, SHALL получать те же значения, кроме имени («Новый детектор») и групп (пусто). Отсутствие ключа `detectors` у существующих пользователей SHALL означать миграцию старых ключей — обновление не меняет поведение молча.

#### Scenario: Дефолтная группа отсутствует в LS

- **WHEN** при первом запуске группа «VPN down» не существует в Little Snitch
- **THEN** группы детектора «Основной» остаются пустыми и в UI показывается подсказка о создании группы

#### Scenario: Новый детектор

- **WHEN** пользователь нажимает «Добавить детектор…»
- **THEN** создаётся включённый детектор «Новый детектор» с маяком Cloudflare, без прокси, в реактивном режиме, без групп, и открываются его детали

#### Scenario: Обновление у существующего пользователя

- **WHEN** приложение обновилось на версию с детекторами, ключа `detectors` в defaults нет
- **THEN** выполняется миграция в детектор «Основной», поведение идентично прежней версии

### Requirement: Окно настроек с вкладками

Приложение SHALL предоставлять окно настроек с вкладками Общие / Детекторы. Изменения SHALL применяться к работающим детекторам без перезапуска приложения; изменение правил детектора учитывается его ближайшей пробой, изменение маяка, прокси или растяжки — перезапуском слоёв этого детектора.

#### Scenario: Переключение мониторинга

- **WHEN** пользователь выключает тумблер «Мониторинг» на вкладке Общие
- **THEN** все детекторы останавливаются без перезапуска приложения

#### Scenario: Редактирование запрещённого egress

- **WHEN** пользователь через редактор списка меняет запрещённые IP детектора
- **THEN** новый список сохраняется и учитывается ближайшей пробой этого детектора

#### Scenario: Смена прокси детектора

- **WHEN** пользователь меняет адрес прокси у включённого детектора
- **THEN** растяжка детектора переустанавливается через новый прокси и выполняется немедленная проба

### Requirement: Контрол режима защиты

Детали детектора SHALL содержать в карточке «Детектор» контрол «Режим защиты» с выбором из двух значений — «Блокировать при утечке» (реактивный) и «Открывать только при VPN» (строгий) — и поясняющей подписью под выбранным значением. Изменение SHALL применяться немедленно: reconcile по объединённой цели с новым режимом детектора (см. state-machine), синхронизация failsafe-конфигурации helper, запись в журнал с именем детектора. На вкладке «Общие» карточки режима защиты SHALL NOT быть.

#### Scenario: Включение строгого режима из настроек

- **WHEN** пользователь переключает режим детектора на «Открывать только при VPN» при его текущем вердикте Offline
- **THEN** группы детектора немедленно включаются, helper получает failsafe-конфигурацию, в журнале появляется запись о переключении с именем детектора

#### Scenario: Подпись объясняет режим

- **WHEN** у детектора выбран строгий режим
- **THEN** подпись под контролом объясняет: трафик по этому пути открыт только при подтверждённом VPN; пауза, выход и сбой приложения закрывают его группы

## ADDED Requirements

### Requirement: Список детекторов

Вкладка «Детекторы» SHALL показывать карточку со списком всех детекторов: у строки — иконка по состоянию детектора, имя, подпись «прокси · режим · группы» (например, «SOCKS5 203.0.113.5:1080 · реактивный · Telegram»; без прокси — «без прокси»; без групп — «нет групп»), чип состояния («Защищён», «Утечка», «Офлайн», «Проверка», «Выключен»), переход в детали по нажатию. Под карточкой SHALL быть кнопка «Добавить детектор…» и счётчик «N детекторов · M включены». Ниже SHALL располагаться общие для всех детекторов настройки: карточка интервалов (heartbeat растяжки, плановая проба, таймаут пробы) с примечанием о подтверждении утечки и карточка «Прямой IP сети» (прямой РУ-IP с давностью, URL РУ-маяков).

#### Scenario: Открытие вкладки

- **WHEN** пользователь открывает вкладку «Детекторы» при трёх детекторах, один из которых выключен
- **THEN** список показывает три строки с состояниями, выключенный — с чипом «Выключен» и приглушённой иконкой, счётчик «3 детектора · 2 включены»

#### Scenario: Переход в детали

- **WHEN** пользователь нажимает строку детектора
- **THEN** содержимое вкладки заменяется экраном деталей этого детектора со строкой возврата «Детекторы»

#### Scenario: Общие настройки под списком

- **WHEN** пользователь меняет «Плановая свежая проба» под списком
- **THEN** новый интервал действует для всех детекторов

### Requirement: Детали детектора

Экран деталей детектора SHALL содержать сверху строку возврата «Детекторы», имя детектора, чип состояния и тумблер «включён»; далее карточки: «Детектор» (поле «Название», контрол режима защиты); «Путь» (сегмент «Прокси»: Нет / HTTP CONNECT / SOCKS5; поле «Адрес прокси» вида хост:порт; тумблер «Растяжка»); «Маяк» (поля основного и резервного URL, сегмент «Формат ответа»: cdn-cgi/trace / голый IP); «Ожидаемый egress» (тумблер «warp=on считается защитой», редактор ожидаемых IP со счётчиком); «Запрещённый egress» (редактор запрещённых IP со счётчиком, прямой IP сети только для чтения с подписью «общий для всех детекторов»); «Группы» (см. rule-group-control, «Список групп в деталях детектора», с футером «Обновить список из LS» и статусом helper). Внизу SHALL быть кнопки «Удалить детектор…» (обычная кнопка с красным заголовком, слева) и «Дублировать» (справа). Удаление SHALL требовать подтверждения с указанием последствий для групп; дублирование SHALL создавать выключенную копию с именем «<имя> (копия)». Адрес прокси SHALL валидироваться как хост и порт 1–65535, URL маяков — как `http(s)`; невалидное значение SHALL NOT сохраняться и SHALL подсвечиваться.

#### Scenario: Детали детектора через прокси

- **WHEN** пользователь открывает детали детектора с SOCKS5-прокси и выключенным флагом warp
- **THEN** сегмент «Прокси» показывает SOCKS5, поле адреса — хост:порт, тумблер «warp=on считается защитой» выключен, список групп отмечен по маппингу этого детектора

#### Scenario: Удаление с подтверждением

- **WHEN** пользователь нажимает «Удалить детектор…»
- **THEN** показывается подтверждение с именем детектора и последствиями для его групп; после подтверждения детектор удалён, экран возвращается к списку

#### Scenario: Дублирование

- **WHEN** пользователь нажимает «Дублировать»
- **THEN** в списке появляется выключенная копия с теми же настройками и именем «<имя> (копия)»

#### Scenario: Невалидный адрес прокси

- **WHEN** пользователь вводит в «Адрес прокси» строку без порта
- **THEN** значение не сохраняется, поле подсвечено ошибкой, прежний адрес остаётся в силе

### Requirement: Миграция настроек одного детектора

При загрузке настроек без ключа `detectors` приложение SHALL один раз собрать детектор «Основной» из ключей `expectedIPs`, `forbiddenEgressIPs`, `leakGroups` и `protectionMode` (без прокси, маяк Cloudflare формата `cdn-cgi/trace`, «`warp=on` считается защитой» включено, растяжка включена), записать массив детекторов и сделать запись в журнал о миграции с составом детектора. Старые ключи SHALL NOT удаляться и SHALL NOT перезаписываться, чтобы откат на прежнюю версию читал прежние значения. Скрытые debug-рычаги `debugIgnoreWarp` и `debugFakeEgressIP` SHALL оставаться глобальными и действовать на все детекторы.

#### Scenario: Обновление с настроенным маппингом

- **WHEN** у пользователя были `leakGroups=["VPN down"]`, `expectedIPs=["192.0.2.10"]` и `protectionMode=strict`, и приложение запущено новой версией
- **THEN** появляется детектор «Основной» в строгом режиме с ожидаемым IP `192.0.2.10` и группой «VPN down», в журнале запись о миграции, поведение совпадает с прежним

#### Scenario: Откат версии

- **WHEN** после миграции пользователь вернул прежнюю версию приложения
- **THEN** она читает нетронутые старые ключи и работает, как до обновления

#### Scenario: Чистая установка

- **WHEN** приложение установлено впервые и старых ключей нет
- **THEN** создаётся детектор «Основной» по значениям по умолчанию, записи о миграции нет

#### Scenario: Debug-рычаг действует на все детекторы

- **WHEN** через `defaults write` включён `debugIgnoreWarp`
- **THEN** `warp=on` не считается защитой ни у одного детектора до снятия рычага
