# design — поддержка remote-групп Little Snitch

## Context

Мотивация — в proposal.md. Здесь только то, что определяет подход.

**Фактическая форма `groups` в `export-model` (Little Snitch 6.5, снято 2026-09-09):**

| `type` | Где имя | `isActive` | Прочее |
| --- | --- | --- | --- |
| `builtinMacOSServices`, `builtinICloudServices` | нет; имя по типу | только у включённых | `updateInterval` |
| `loadedFromFile` | `userProvidedName` | только у включённых | `creationDate` |
| `loadedFromURL` | `factoryName` (+ `factoryDescription`) | только у включённых | `loadFromURL`, `lastSuccessfulUpdate`, `lastModifyingUpdateCachingIdentifier`, `updateInterval` |

В июльском снимке (фикстура `LittleSnitchModelTests`) у той же локальной группы `ghoGzc` ключа `type` не было — сейчас он есть. Вывод: `type` у локальных групп нестабилен между версиями LS, а поля имени стабильны.

**Что подтверждено на машине:** `sudo littlesnitch rulegroup -d "Require VPN Services"` завершается кодом 0 без вывода — CLI принимает `factoryName` подписки как имя. Флаг `-u <user>` не нужен: root видит подписку в общей модели.

**Что не подтверждено:** ключ, под которым LS хранит пользовательское имя переименованной подписки. В бинаре CLI у класса `LSRuleGroup` есть свойство `customName`, в дампе оно не встретилось (подписка не переименована). Документация LS говорит, что переименовать подписку можно.

**Текущий конвейер имени:**

```
export-model --> RuleGroupModelParser.parseLittleSnitchGroups
                   userProvidedName?  --> имя          (local)
                   type builtin*?     --> имя по типу  (builtin)
                   иначе              --> continue     <-- подписка теряется здесь
             --> RuleGroupInfo(name, enabled) --JSON/XPC--> HelperRuleGroup
             --> RuleGroup(name, enabled) --> вкладка «Группы», LeakPolicy.plan по имени
             --> littlesnitch rulegroup -e/-d <имя>
```

Общий толерантный поиск по форме объекта (`collect`) запускается только когда основной путь не нашёл ни одной группы — на реальной модели он не работает никогда, хотя в его `groupContainerKeys` уже есть `subscribedRuleGroups`.

**Ограничения проекта:** `Domain/` — чистый Swift; XPC-контракт узкий и перечислимый; helper пересобирается ⇒ приложение видит смену отпечатка и предлагает переустановку; регистрировать helper только из `~/Applications` (ловушка BTM с DerivedData).

## Goals / Non-Goals

**Goals:**

- Подписанные группы видны в списке и управляются reconcile так же, как локальные.
- Пользователь отличает подписку от одноимённой локальной копии во вкладке «Группы».
- Разбор модели не зависит от `type` локальных групп и переживает появление новых полей.
- Одноимённые группы не приводят ни к падению интерфейса, ни к молчаливому выбору.
- Контракт XPC расширяется совместимо: старый helper и новое приложение (и наоборот) не ломаются.

**Non-Goals:**

- Blocklists Little Snitch: в дампе их нет, форма записи не подтверждена. Если они лежат в `groups` с `type: loadedFromURL`, они появятся в списке как подписки — CLI переключает их той же командой, это приемлемо.
- Дата последнего обновления подписки в интерфейсе (`lastSuccessfulUpdate`): отдельная нить.
- Идентификация групп по внутреннему id LS вместо имени: `rulegroup -e/-d` принимает только имя, id ничего не даст.
- Различение одноимённых групп при включении: невозможно на уровне CLI.

## Decisions

### Решение 1: имя по цепочке полей, а не по `type`

Имя берётся первым непустым из `userProvidedName` → `customName` → `factoryName`; если ни одного нет — имя по известному встроенному `type`; иначе запись пропускается. `type` используется только для вида группы и для встроенных имён.

*Почему:* у локальной группы `type` за два месяца сменился с отсутствующего на `loadedFromFile`; завязка на `type` сломалась бы на следующем обновлении LS. Поля имени — то, что LS показывает пользователю, они стабильны по смыслу.

*Альтернатива:* `switch type` с веткой на каждый вид — отвергнута: хрупко, и каждая новая версия LS требовала бы правки.

### Решение 2: пропускать безымянное, а не незнакомое

Единственная причина пропустить запись — отсутствие имени. Нынешний тест «группа неизвестного встроенного типа пропускается» сохраняется как «безымянная запись пропускается»: у встроенных незнакомых типов имени нет, у подписок есть.

### Решение 3: `customName` выше `factoryName` (допущение)

Для переименованной подписки берётся `customName`. Если ключ окажется другим, меняется одна строка в цепочке и фикстура; спека описывает наблюдаемое поведение («под пользовательским именем») и не зависит от ключа. Проверка — в живой приёмке: переименовать подписку в LS, снять `export-model`, убедиться, что `rulegroup -d` принимает новое имя.

### Решение 4: вид группы — необязательное поле `kind` в том же JSON

`RuleGroupInfo` получает `kind: String` со значениями `builtin` / `local` / `remote`; строки-константы живут в `HelperProtocol.swift`, который компилируется и в helper, и в приложение. `HelperRuleGroup` в шлюзе декодирует поле как опциональное: отсутствие или незнакомая строка ⇒ `nil`. В домене — `enum RuleGroupKind { builtin, local, remote }` и `RuleGroup.kind: RuleGroupKind?` с `nil` по умолчанию, чтобы существующие вызовы `RuleGroup(name:enabled:)` не менялись.

*Почему не отдельная XPC-операция:* контракт обязан оставаться перечислимым; расширение JSON необязательным полем ничего не добавляет к поверхности helper.

*Почему опционал, а не `.unknown`:* «helper не сообщил» — не свойство группы, а свойство ответа; в домене вид либо известен, либо нет.

### Решение 5: дубликаты схлопывает приложение, а не helper

Парсер возвращает массив в детерминированном порядке (имя по `localizedStandardCompare`, при равенстве — вид в порядке local, builtin, remote) и **не** схлопывает одноимённые. `SyncRuleGroups` оставляет первую запись на каждое имя и пишет в журнал `.warning` с именем. Вкладка «Группы» продолжает использовать имя как идентификатор строки — уникальность гарантирована схлопыванием.

*Почему не в helper:* журнал — единственный канал диагностики для пользователя, а он живёт в приложении; helper может только `os.Logger`. Молчаливое схлопывание в парсере спрятало бы проблему, которую пользователь может решить одним переименованием в LS.

### Решение 6: запасной поиск по форме узнаёт новые поля имени

`nameKeys` общего поиска дополняются `customName` и `factoryName`. Основной путь по-прежнему первый; запасной остаётся страховкой на смену формата.

### Решение 7: без новой настройки и без миграции

Идентификатор в `leakGroups` — имя. Запись «Require VPN Services» в настройках целевой машины начинает работать сразу после переустановки helper. Локальную копию «Require VPN Services Local» пользователь убирает из маппинга сам, если она была обходным путём.

## Risks / Trade-offs

- **[Имя подписки меняется на сервере при обновлении файла]** → группа выпадает из маппинга; срабатывает существующий сценарий «несуществующее имя»: ошибка в журнале и уведомление. Пользователь заново отмечает группу. Документируется в README.
- **[Ключ пользовательского имени не `customName`]** → переименованная подписка показывается под именем из файла, а `rulegroup -e` может это имя не принять. Ловится живой приёмкой; правка локальна.
- **[Одноимённые локальная и подписка: CLI переключит неизвестно какую]** → предупреждение в журнале; рекомендация в README — держать имена уникальными.
- **[Blocklists окажутся в `groups` как `loadedFromURL`]** → появятся в списке как подписки и будут управляемы той же командой; вид «blocklist» не различается до подтверждения формы.
- **[Рассинхрон версий приложения и helper]** → штатная проверка отпечатка предлагает переустановку; декодер терпим к отсутствию `kind`, так что и до переустановки список читается.

## Migration Plan

1. Реализация по tasks.md, тесты зелёные, CI на обоих macOS.
2. Сборка и регистрация helper из `~/Applications` (не из DerivedData); приложение заметит смену отпечатка и предложит переустановить демон.
3. Открыть вкладку «Группы»: подписка появляется с подписью «подписка», состояние совпадает с LS.
4. Откат — обычный revert: подписки снова пропадают из списка, ничего персистентного не создаётся.

## Open Questions

- Под каким ключом LS хранит пользовательское имя переименованной подписки (`customName` — допущение). Проверяется в живой приёмке; на спеки и разбиение задач не влияет.
- Попадают ли blocklists в `groups` и с каким `type`. Проверить, когда на целевой машине появится хотя бы один; вне скоупа.
