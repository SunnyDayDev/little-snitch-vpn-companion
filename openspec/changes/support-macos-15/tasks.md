## 4. Приёмка на живой Sequoia

Выполняется на машине с macOS 15.7+ (design, решение 5). **Результат:** целевая машина оказалась Intel на macOS 15.7.8; приложение собрано на Apple Silicon и перенесено готовым бандлом (см. группу 5), работает несколько дней без отличий в поведении от 26.x.

- [x] 4.1 Универсальный бандл, подписанный настоящим сертификатом, перенесён на целевую машину и запускается (сборка на самой машине неприменима — Xcode 26 для Intel в App Store не отдаётся)
- [x] 4.2 Онбординг целиком: установка helper, одобрение объекта входа (`SMAppService.openSystemSettingsLoginItems()` открывает нужный раздел System Settings в Sequoia), разрешение уведомлений
- [x] 4.3 XPC работает: helper отвечает и переключает группы (следует из 4.4/4.5). Строгий requirement — по артефакту, а не чтением лога: helper в перенесённом бандле подписан сертификатом (`Authority=little-snitch-vpn-companion`), а ad-hoc-фолбэк в `ClientRequirement` срабатывает только при отсутствии сертификата в подписи
- [x] 4.4 Переключение групп: `defaults write dev.sunnyday.lsvpncompanion debugIgnoreWarp -bool true` → за ≤5 с Leak и группы включены; снятие флага → Protected и группы выключены; события в журнале
- [x] 4.5 Строгий режим: закрытие при пропаже сети (Wi-Fi off) и при выходе из приложения (⌘Q); dead-man's switch helper после принудительного завершения приложения
- [x] 4.6 Внешний вид: скриншоты поповера, настроек и онбординга на Sequoia — расхождения только косметические (нет системного «стекла» macOS 26), верстка не ломается
- [x] 4.7 Результат приёмки зафиксирован в `README.md`: диапазон 15.7–26.x, обе границы проверены живой эксплуатацией (26.x на Apple Silicon, 15.7.8 на Intel)

## 5. Универсальный артефакт и перенос

Вскрылось на приёмке: целевая машина — Intel, Xcode там недоступен, поэтому единственный путь — собрать на Apple Silicon и перенести бандл.

- [x] 5.1 `ARCHS = "arm64 x86_64"` задан явно в `project.yml` — не полагаемся на `ARCHS_STANDARD`, из которого Apple однажды уберёт x86_64
- [x] 5.2 Проверка: `lipo -archs` даёт `x86_64 arm64` у приложения и у helper; подпись переживает упаковку `ditto` (`codesign --verify --strict --deep` после распаковки)
- [x] 5.3 `README.md`: раздел «Перенос на другую машину» — упаковка, карантин и обход Gatekeeper в Sequoia, распаковка сразу в `~/Applications`, почему сертификат переносить не нужно
