# Строгий режим защиты (fail-closed)

## Why

Сегодня приложение работает только в реактивной парадигме: группы Little Snitch включаются лишь при доказанной утечке, а во всех неопределённых ситуациях (старт, пропажа/смена сети, выход приложения, загрузка ОС) foreign-трафик остаётся открытым. Для пользователя, которому «страшно выйти без VPN», это неприемлемо: между сменой сети и вердиктом пробы, между загрузкой ОС и стартом приложения, после крэша приложения — трафик течёт напрямую.

## What Changes

- Появляется настройка **«Режим защиты»** с двумя значениями:
  - **Реактивный** (текущее поведение, остаётся дефолтом): закрываем при доказанной утечке;
  - **Строгий** (fail-closed): группы выключены (трафик открыт) **только** при доказанном VPN. Инвариант: *«группы выключены ⇔ последний вердикт Protected и мониторинг работает»*.
- В строгом режиме закрывают трафик: старт приложения (до первого вердикта), пропажа сети, смена сети (до успешной проверки), пауза мониторинга и выключение тумблера мониторинга, выход из приложения (включая ⌘Q), крэш приложения (dead-man's switch в helper), загрузка ОС до старта приложения (RunAtLoad-закрытие в helper + персистентность групп самим Little Snitch).
- Новое доменное состояние **Checking** («сеть есть, вердикта ещё нет») — честно отражается в иконке, поповере и журнале.
- Пропажа сети (path unsatisfied) становится немедленным сигналом Offline — без ожидания таймаута пробы; вердикты проб, запущенных до пропажи сети, отбрасываются. Это улучшение действует в обоих режимах.
- Helper расширяется: персистентный failsafe-конфиг (режим + список групп), супервизия XPC-соединения с приложением (закрытие групп при исчезновении клиента), закрытие групп на загрузке ОС.
- Эскалация (Wi-Fi off) в строгом режиме дополнительно срабатывает при «вердикт Leak + не удалось закрыть группы»; при Offline/Checking эскалации нет (captive portal, отсутствие сети — Wi-Fi off там враждебен).
- UI: карточка «Режим защиты» в настройках (сегмент-контрол), warn-баннер и тексты поповера для «закрыто без утечки», пятый глиф иконки строки меню, предупреждение «не включайте браузер и VPN-клиент в управляемые группы».
- Никакого escape hatch типа «Открыть на N минут» не делаем: ручной выход из строгого закрытия — средствами самого Little Snitch (осознанное решение).

## Capabilities

### New Capabilities

Нет: изменение целиком выражается дельтами существующих capabilities.

### Modified Capabilities

- `state-machine`: новое состояние Checking; таблица переходов параметризуется режимом (в строгом Offline/Checking/Paused закрывают группы); пауза в строгом режиме закрывает; на старте сначала закрытие, потом проба; семантика переключения режима на лету.
- `egress-detection`: пропажа сети (path unsatisfied) — немедленный Offline-сигнал без пробы; инвалидация вердиктов проб в полёте; смена сети в строгом режиме сначала закрывает, потом проверяет.
- `rule-group-control`: маппинг «состояние → группы» становится функцией режима (строгий: всё, кроме Protected → включены); расширение XPC-контракта failsafe-операциями; персистентный конфиг helper; dead-man's switch; закрытие на загрузке ОС.
- `failsafe-escalation`: условие эскалации в строгом режиме («Leak + не удалось закрыть»); приоритет observeOnly над строгим режимом.
- `app-settings`: ключ `protectionMode` (дефолт reactive, без миграции); контрол в «Общие»; немедленный reconcile при переключении режима.
- `menu-bar-ui`: иконка и поповер для Checking и для «закрыто без утечки» (warn-семантика); режимо-зависимые тексты.
- `onboarding`: предупреждение о составе управляемых групп (не включать браузер и VPN-клиент).

## Impact

- **Domain**: `EgressState` (+`checking`), `StateMachine` (события pathDown/режим, порядок эффектов на старте/паузе), `LeakPolicy` (параметр режима).
- **Application**: `MonitoringCoordinator` (немедленное закрытие, инвалидация проб, порядок reconcile→stop при паузе), `ApplyPolicy`, `AppSettings`.
- **App**: делегат приложения для обработки завершения (сейчас отсутствует), `AppModel`, поповер, настройки, онбординг, `DSStatusIcon`.
- **Helper**: новые XPC-операции, персистентный конфиг в `/Library/Application Support/<label>/`, обработчики invalidation, RunAtLoad в plist (требует спайк-проверки на живой машине).
- **Infrastructure**: `DefaultsSettingsStore` (+ключ), `HelperRuleGroupGateway` (+операции), `SystemPathMonitor` (сигнал unsatisfied уже есть в `NetworkPathInfo`).
- **Tests**: существующие fail-open тесты становятся веткой reactive; зеркальная матрица для strict; новые фейки-сценарии (подвешенная проба, pathDown-гонка).
- **Документы**: SPEC.md §1, §3, §5, ФТ-2/5/7/9/10, §7, §10.2, §13, §14, §15; макеты `design/app.pen` (новые фреймы поповера, карточка режима, ряд иконок — light+dark).
- **Обратная совместимость**: дефолт reactive, существующие пользователи не замечают изменений; helper-протокол расширяется аддитивно (проверка версии уже есть).
