# state-machine — дельта

## MODIFIED Requirements

### Requirement: Множество состояний

Доменная модель SHALL определять состояния `Protected`, `Leak`, `Offline`, `Checking`, `Paused` и отдельный (ортогональный состоянию) флаг «helper недоступен».

`Checking` — «сеть есть, вердикта ещё нет»: в него входят только в строгом режиме защиты (старт мониторинга, смена/появление сети); в реактивном режиме состояние до вердикта сохраняется прежним, как сейчас.

#### Scenario: Флаг helper недоступен не меняет состояние

- **WHEN** вызов helper завершился ошибкой при текущем состоянии Leak
- **THEN** состояние остаётся Leak, взводится флаг «helper недоступен»

#### Scenario: Checking не возникает в реактивном режиме

- **WHEN** режим защиты реактивный и произошла смена сетевого пути при состоянии Protected
- **THEN** состояние остаётся Protected до вердикта пробы, Checking не используется

### Requirement: Таблица переходов

State machine SHALL реализовывать переходы, часть которых зависит от режима защиты (Р — реактивный, С — строгий):

| Из | Событие | В | Действия (Р) | Действия (С) |
|---|---|---|---|---|
| любое (кроме Paused) | проба ×2 = чужой egress | Leak | reconcile: включить группы; уведомление | то же |
| Leak | проба = защищён | Protected | reconcile: выключить группы; уведомление | то же |
| Offline/Checking | проба = защищён | Protected | reconcile по результату | reconcile: выключить группы |
| Protected | обрыв растяжки / смена пути (сеть жива) | — | немедленная проба | немедленная проба; группы НЕ трогать (мягкая проверка: закрывает вердикт, не событие) |
| Offline/Checking | обрыв растяжки / смена пути (сеть жива) | — (Р) / Checking (С) | немедленная проба | Checking; группы остаются закрыты; немедленная проба |
| любое (кроме Paused) | сеть пропала (path unsatisfied) | Offline | группы НЕ трогать | закрыть группы |
| Protected/Leak | пробы не отвечают | Offline | группы НЕ трогать | закрыть группы |
| любое | пользователь: Пауза | Paused | группы НЕ трогать; детектор остановить | закрыть группы, ЗАТЕМ остановить детектор |
| Paused | пользователь: Возобновить | по пробе (Р) / Checking (С) | немедленная проба + reconcile | закрыто; открытие только по вердикту Protected |
| Leak | helper не отвечает | Leak | эскалация, если включена | то же |
| старт приложения | — | по пробе (Р) / Checking (С) | немедленная проба + reconcile | СНАЧАЛА закрыть группы, потом проба |

Мягкие проверки из устойчивого Protected — осознанное решение: события пути и обрывы растяжки часты, вердикт может протухнуть сразу после проверки и без них, а каждое превентивное закрытие — потерянные запросы. Закрытие в строгом режиме наступает по фактам (offline-вердикт, пропажа сети, подтверждённая утечка) и на границах неопределённости (старт, возврат сети, возобновление, выход), а не по каждому поводу для проверки.

#### Scenario: Подтверждённая утечка из Protected

- **WHEN** состояние Protected и две пробы подряд дали чужой egress
- **THEN** состояние становится Leak, выполняется reconcile (включить группы маппинга) и отправляется уведомление

#### Scenario: Восстановление из Leak

- **WHEN** состояние Leak и проба дала protected
- **THEN** состояние становится Protected, выполняется reconcile (выключить группы) и отправляется уведомление

#### Scenario: Пробы перестали отвечать (реактивный)

- **WHEN** режим реактивный, состояние Protected или Leak и пробы не отвечают (offline-результаты)
- **THEN** состояние становится Offline, группы LS не изменяются

#### Scenario: Пробы перестали отвечать (строгий)

- **WHEN** режим строгий, состояние Protected и пробы не отвечают
- **THEN** состояние становится Offline и выполняется закрывающий reconcile (группы включаются)

#### Scenario: Смена сети из открытого состояния — мягкая проверка

- **WHEN** режим строгий, состояние Protected и сетевой путь изменился (сеть жива)
- **THEN** состояние остаётся Protected и группы не трогаются; запускается немедленная проба, и закрывает только её вердикт (offline → закрыть; утечка ×2 → Leak)

#### Scenario: Сеть вернулась в строгом режиме

- **WHEN** режим строгий, состояние Offline (группы включены) и сеть появилась
- **THEN** состояние становится Checking, группы остаются включены, запускается немедленная проба; группы выключаются только после вердикта protected

#### Scenario: Сеть вернулась в реактивном режиме

- **WHEN** режим реактивный, состояние Offline и проба ответила
- **THEN** состояние становится Protected или Leak по результату пробы и выполняется reconcile

#### Scenario: Пауза пользователем (реактивный)

- **WHEN** режим реактивный и пользователь ставит мониторинг на паузу из любого состояния
- **THEN** состояние становится Paused, детектор останавливается, группы LS не изменяются

#### Scenario: Пауза пользователем (строгий)

- **WHEN** режим строгий и пользователь ставит мониторинг на паузу из состояния Protected
- **THEN** сначала выполняется закрывающий reconcile (группы включаются), затем состояние становится Paused и детектор останавливается

#### Scenario: Возобновление после паузы (строгий)

- **WHEN** режим строгий и пользователь возобновляет мониторинг из Paused
- **THEN** состояние становится Checking (группы остаются включены), выполняется немедленная проба; группы выключаются только по вердикту protected

#### Scenario: В паузе утечка игнорируется

- **WHEN** состояние Paused и egress фактически чужой
- **THEN** никакие пробы не выполняются, переходов нет

#### Scenario: Старт приложения (строгий)

- **WHEN** режим строгий и мониторинг стартует
- **THEN** состояние становится Checking, закрывающий reconcile выполняется ДО первой пробы, затем запускается проба

#### Scenario: Вердикт устаревшей пробы отбрасывается после пропажи сети

- **WHEN** проба запущена, затем сеть пропала (path unsatisfied), затем проба вернула protected
- **THEN** вердикт отбрасывается: состояние остаётся Offline, открывающий reconcile не выполняется

### Requirement: Reconcile вместо истории

При каждом переходе состояний и на старте система SHALL сверять фактическое состояние rule groups Little Snitch с целевым набором, определяемым парой «текущее состояние + режим защиты», и приводить к нему (reconcile). Система SHALL NOT полагаться на память о ранее выполненных включениях/выключениях. Повторное включение уже включённой группы — допустимая no-op операция.

#### Scenario: Reconcile на старте при рассинхроне

- **WHEN** приложение стартует в Protected (реактивный режим), а группа маппинга фактически включена в LS (осталась с прошлого раза)
- **THEN** reconcile выключает группу

#### Scenario: Идемпотентность reconcile

- **WHEN** reconcile требует включить группу, которая уже включена
- **THEN** операция выполняется без ошибки и не меняет наблюдаемое состояние

## ADDED Requirements

### Requirement: Инвариант строгого режима

В строгом режиме защиты система SHALL гарантировать: управляемые группы выключены (foreign-трафик открыт) тогда и только тогда, когда последний вердикт детектора — Protected и мониторинг активен. Во всех остальных ситуациях (Leak, Offline, Checking, Paused, мониторинг выключен, приложение не работает) группы SHALL быть включены.

#### Scenario: Единственная дверь в «открыто»

- **WHEN** режим строгий и группы фактически выключены
- **THEN** последним применённым вердиктом был Protected при активном мониторинге

#### Scenario: Выключение тумблера мониторинга закрывает

- **WHEN** режим строгий, состояние Protected и пользователь выключает тумблер «Мониторинг»
- **THEN** перед остановкой детектора выполняется закрывающий reconcile (группы включаются)

### Requirement: Переключение режима на лету

Переключение режима защиты SHALL применяться немедленно, без перезапуска приложения, с записью в журнал и немедленным reconcile по политике нового режима: при переходе «реактивный → строгий» группы SHALL включаться, если текущий вердикт не Protected; при переходе «строгий → реактивный» группы SHALL выключаться, если текущий вердикт не Leak (иначе пользователь остался бы закрытым без агента, который это закрытие снимет).

#### Scenario: Включение строгого режима без VPN

- **WHEN** режим реактивный, состояние Offline и пользователь переключает режим на строгий
- **THEN** группы немедленно включаются, в журнал пишется переключение режима

#### Scenario: Возврат в реактивный режим из паузы

- **WHEN** режим строгий, состояние Paused (группы включены) и пользователь переключает режим на реактивный
- **THEN** группы немедленно выключаются (вердикт не Leak), в журнал пишется переключение режима

#### Scenario: Возврат в реактивный при утечке

- **WHEN** режим строгий, состояние Leak и пользователь переключает режим на реактивный
- **THEN** группы остаются включены (Leak закрывает в обоих режимах)
