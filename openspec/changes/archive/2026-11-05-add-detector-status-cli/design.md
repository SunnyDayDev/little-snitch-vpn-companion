# Дизайн

## Context

Мотивация и границы пользовательского запроса описаны в `proposal.md`, внешний контракт — в `specs/detector-status-cli/spec.md`.

`MonitoringCoordinator` — actor с принятыми состояниями и `MonitoringSnapshot`. Его снимок уже включает все детекторы, `AggregateStatus`, `groupsStateKnown`, `activeLeakGroups`, `helperUnavailable`. `DetectorSnapshot.explanation` отделён от сырого `trace`: тест `StatusExplanationTests.confirmationKeepsAcceptedEvidence` показывает, что первая подозрительная проба обновляет trace, но ещё не меняет Protected и его основание. Поэтому сериализация `trace` дала бы неверный статус.

Снимок не содержит полного жизненного цикла мониторинга и `observeOnly`: эти сведения доступны координатору как `isRunning`, `isPaused`, `appliedObserveOnly`. `AppModel` получает снимки асинхронно через MainActor и может отставать. `CompositionRoot` собирает инфраструктуру; запуск модели выполняется из живущего с приложением лейбла строки меню. Helper предоставляет операции групп и failsafe, но вердиктов детекторов не хранит.

В `project.yml` уже заданы две архитектуры и macOS 15.7+. Схема `Tests` нужна для macOS 15 без компиляции иконки приложения. Скрипты установки и релиза собирают приложение и копируют бандл целиком; CLI должен стать его вложенным исполняемым файлом.

## Goals / Non-Goals

**Цели:** один источник вердиктов для UI и терминала; согласованный ответ без ожидания новой пробы; простой независимый от SwiftUI клиент; доступность сервера при остановленном мониторинге.

**Вне границ:** самостоятельная детекция без приложения, `check`, `watch`, изменение настроек, управление группами, автозапуск приложения из CLI, сетевой API, публикация релиза. Код классификатора и таблицы Domain не меняются.

## Decisions

### 1. Чтение в координаторе, отдельная проекция

Добавить операцию чтения статуса в `MonitoringCoordinator`. Получив время через существующий `Clock`, она без следующих точек suspension собирает снимок и копирует жизненный цикл и применённый `observeOnly`. Выключенный общий тумблер даёт `stopped`; при включённом тумблере `paused` имеет приоритет над `isRunning`, далее `running` либо `stopped`. Применённый `monitoringEnabled` хранится рядом с `appliedObserveOnly`: общий тумблер использует в AppModel тот же путь остановки детекторов, что и пауза, поэтому одного `isPaused` недостаточно. Метка `capturedAt` относится к этому чтению, `lastCheck` — к прежнему наблюдению. Новые пробы и reconcile не вызываются.

Проекцию в типы CLI вынести в `Application/`: принимать только готовые значения, не читать defaults повторно между полями ответа. Полный ответ и фильтрация строятся из одного снимка. Использовать `DetectorSnapshot.explanation`; при несовпадении вида основания с состоянием возвращать `null`. Для выключенного детектора: `state=disabled`, `lastCheck=null`, `explanation=null`, `tripwireActive=false`. `diagnosis` и сырой `trace` отдельно не экспортировать.

Альтернатива — читать `AppModel.snapshot` — добавляет задержку доставки MainActor. Чтение defaults даёт конфигурацию, чтение журнала — историю: ни одно не является текущим состоянием.

### 2. Общий контракт без зависимости CLI от приложения

Добавить общий каталог `StatusProtocol/` с `Codable`, `Sendable` DTO, версией и кодами ошибок. DTO используют строки, числа, массивы и опциональные поля; они не зависят от SwiftUI, AppKit, helper и доменных ассоциированных enum. Приложение и CLI компилируют эти исходники напрямую, как сейчас разделяется `HelperProtocol.swift`. Формат enum кодируется явно, а не синтезом структуры Swift.

Корень успешного JSON версии 1:

| Поле | Значение |
| --- | --- |
| `schemaVersion` | целое `1` |
| `capturedAt` | строка ISO 8601 UTC с миллисекундами |
| `monitoring` | `running`, `paused`, `stopped` |
| `observeOnly` | Bool |
| `helperUnavailable` | Bool из снимка, не утверждение об установленности helper |
| `groups` | `{known: Bool, active: [String] либо null}`; контекст всего приложения |
| `overall` | только без фильтра: `{state, culpritID, hasEnabledDetectors, hasStrictClosed}` |
| `detectors` | только без фильтра: массив объектов в порядке настроек |
| `detector` | только с фильтром: один объект |

Поля детектора: `id`, `name`, `isEnabled`, `mode` (`reactive`/`strict`), `state` (`protected`, `leak`, `offline`, `checking`, `paused`, `disabled`), `explanation`, `lastCheck` (ISO 8601 UTC либо null), `tripwireActive`, `assignedGroups`. `overall.state` использует доменные состояния без `disabled`; `culpritID` допускает null. `hasStrictClosed` — существующий признак сводки, а не доказательство успешной блокировки: фактическое состояние берётся из `groups` с учётом `observeOnly`.

Варианты `explanation`:

- `null` — достоверного основания нет, Checking, Paused либо disabled;
- `{kind: "protected", expectedIP: String|null, warp: "on"|"plus"|null}` — только реально участвовавшие признаки;
- `{kind: "leak", ip: String, diagnosis: "forbiddenServer"|"directRuIP"|"foreignEgress"}`;
- `{kind: "offline", cause: "noNetwork"|"beaconUnavailable"|"unknown"}`.

Внутри соответствующего варианта перечисленные поля обязательны; неизвестные опциональные значения кодируются как явный null. Назначенные группы не выдаются за реально включённые. Состав `groups.active` при `known=false` принудительно null: сохранённые имена не трактуются как свежие сведения. Конфигурационные allowlist/denylist, адреса прокси и сырое тело маяка не экспортируются. Наблюдённые адреса из принятого основания передаются только в ответе, новый файл со снимком не создаётся.

Совместимые дополнительные поля разрешены внутри версии 1. Клиент игнорирует неизвестные поля, но проверяет обязательные поля, версию и допустимые enum; несовместимая версия или неверная структура дают код 5. Другой набор обязательных полей или изменение смысла требуют новой версии.

### 3. Локальный Unix-сокет пользователя

Сервер работает внутри приложения, клиент подключается через Unix domain socket. Это новый канал только для чтения, не расширение root-helper. TCP не нужен. XPC Mach service потребовал бы отдельного решения регистрации и обнаружения сервиса графического приложения; файл со снимком потребовал бы доказательства живости и создавал бы устаревающую копию статуса.

В инфраструктуре разместить общий resolver пути и реализацию транспорта на Foundation/Darwin. Использовать короткую подпапку `lsvpn` системного временного каталога пользователя, сокет `status.sock`. Оба процесса вычисляют путь одинаково средствами ОС, без зависимости от cwd, PATH или переопределённого `TMPDIR`. До bind проверить вместимость пути; не делать небезопасный запасной путь в общем каталоге.

Каталог принадлежит текущему UID и имеет 0700, сокет — 0600. Не следовать симлинкам при проверках каталога, lock-файла и удалении точки подключения; неожиданный владелец или тип файла — ошибка. Сервер проверяет UID подключившегося процесса, клиент — владельца точки и UID сервера. Граница доверия — пользователь: процессы с тем же UID не отделяются друг от друга подписью.

Владение точкой сервера защищается удерживаемой файловой блокировкой в этом каталоге. Только владелец блокировки после проверок может удалить остаточный собственный сокет и выполнить bind. Вторая копия не удаляет точку первой. При остановке удаляется только созданная данным сервером точка; ошибка запуска пишет одно предупреждение в существующий журнал, мониторинг продолжает работать.

### 4. Ограниченный обмен запросом и ответом

Одна связь обслуживает один запрос и закрывается после ответа. Обрамление — длина UInt32 в сетевом порядке и JSON UTF-8: частичные read/write обрабатываются до полного сообщения. Запрос содержит `{schemaVersion: 1, command: "status", detectorID: String|null}`. Сервер принимает только эту команду. Флаг формата остаётся в CLI: текст и JSON представляют одни и те же данные.

Внутренний ответ транспорта — `{schemaVersion: 1, result: <успешный объект>|null, error: <ошибка>|null}`, строго одно из result/error непустое. Ошибка содержит стабильный `code` и русское `message`. CLI печатает только result при успехе и только message в stderr при ошибке. Неизвестный ID выбирается и проверяется на сервере по тому же снимку.

Общий дедлайн клиента 3 с охватывает connect, запись, чтение и проверку ответа; использовать часы, соответствующие требованию времени бодрствования. У сервера ограничить длительность незавершённой связи и число одновременно обслуживаемых соединений (16). Размер запроса ограничить 16 KiB, ответа — 4 MiB; превышение в клиенте — код 5. Сервер не должен блокировать actor мониторинга и MainActor на операциях сокета или ожидании клиента. Завершённые и отменённые операции закрывают дескрипторы.

Таймаут, отсутствие сервера и обрыв до полного кадра дают код 3; полностью полученный, но некорректный кадр/JSON либо несовместимая версия — 5. До успешной проверки всего ответа ничего не писать в stdout.

### 5. Жизненный цикл сервера

`CompositionRoot` создаёт сервер с замыканием чтения координатора и передаёт владельцу жизненного цикла в AppModel. Запуск выполняется один раз после подготовки модели/настроек и до потенциально долгих действий инфраструктуры. От запуска/остановки сетевого мониторинга сервер независим. Повторная `.task` не создаёт повторный listener.

В начале завершения приложения сервер перестаёт принимать новые запросы, отменяет незавершённые связи и освобождает ресурсы. Это не добавляет ожидания к имеющемуся ограниченному бюджету `prepareForTermination`. Аварийный выход обрабатывается восстановлением при следующем запуске. Сохранение окон, пауза, недоступность helper не останавливают сервер.

### 6. CLI и поставка

Новый tool-таргет с продуктом `lsvpn`: `CLI/` для разбора аргументов, форматирования и точки входа; `StatusProtocol/` и явно перечисленные файлы клиента/resolver из инфраструктуры. CLI не компилирует координатор, проберы, AppModel или helper. Для четырёх форм `status` использовать небольшой явный парсер без новой внешней библиотеки. Справка обрабатывается до подключения; смешивание справки с аргументами, кроме `status --help`, отклоняется как ошибка синтаксиса.

Текстовый вывод на русском без обязательной зависимости от цвета: общий контекст и группы, затем таблица ID/имя/статус/режим/проверка/растяжка и строки основания и назначенных групп. Давность считать относительно capturedAt; пользовательские имена экранировать от управляющих символов терминала. JSON сохраняет исходные имена стандартным JSON-экранированием.

Принятые для первой версии проектные значения: 0 — успешное чтение, 1 — прочая ошибка, 2 — синтаксис, 3 — недоступность/таймаут, 4 — неизвестный ID, 5 — протокол. Leak и отсутствие включённых детекторов не являются ошибками чтения. Проверку «все защищены» скрипт выполняет по JSON, отдельного режима healthcheck нет.

Добавить зависимость приложения от CLI и встраивание в `Contents/MacOS/lsvpn` до финальной подписи, по существующему примеру helper. Сборка обеих архитектур наследуется из проекта. В `Scripts/release.sh` добавить проверку вложенного бинаря на присутствие, архитектуры и подпись без изменения процесса публикации.

Не создавать ссылки в PATH при запуске приложения. `README.md` документирует прямой вызов `"<путь к приложению>/Contents/MacOS/lsvpn"` и явное создание пользователем ссылки `~/.local/bin/lsvpn`, добавление каталога в PATH и обновление ссылки при переносе бандла. `Scripts/install.sh` печатает фактический путь к CLI после установки, не перезаписывая пользовательские команды. Пользовательский путь установки может отличаться от `~/Applications`.

### 7. Проверка

Табличные тесты проекции покрывают каждое состояние и вид основания, выключенный детектор, отсутствие проверок, пустой список, паузу/остановку, observeOnly, неизвестные группы и совпадающие имена. Использовать существующие fake-зависимости координатора, чтобы подтвердить отсутствие дополнительных проб/reconcile от запроса; повторить сценарий первого leak-кандидата из StatusExplanationTests.

Отдельные тесты CLI проверяют четыре сочетания флагов, порядок, синтаксис, справку без сервера, формы JSON и таблицу кодов/потоков. Интеграционные тесты транспорта работают с временным собственным endpoint: частичные кадры, несовместимость, таймаут, обрыв, пределы сообщений, параллельные клиенты, повторный запуск и конкуренция двух серверов. Для ожиданий предусмотреть инъекцию короткого тестового дедлайна. Политику UID и небезопасных путей тестировать отдельно без требования root. Тестовые данные используют только документационные IP.

Добавить новые тестовые источники/таргеты и сборку CLI в обе схемы, включая `Tests`, чтобы macOS 15 проверяла реальный CLI без иконки приложения. До пуша выполнить штатные команды тестирования проекта и check-domain-purity. Приёмка готового бандла: подпись, две архитектуры, `--help`, затем запросы к приложению при закрытом поповере, паузе, остановке и после его завершения.

## Risks / Trade-offs

- Локальный сокет добавляет дескрипторы и гонки запуска → отдельная файловая блокировка, идемпотентный жизненный цикл, тесты аварийного остатка и конкуренции.
- Путь Unix-сокета ограничен → короткие компоненты, общий resolver и явная проверка длины; длинный путь не ломает мониторинг.
- Три секунды могут истечь под нагрузкой → явная ошибка без старого снимка; чтение координатора не ждёт сети или helper.
- Успех CLI не означает Protected → коды описывают чтение, статус и давность проверки передаются отдельно и документируются.
- Фактическое состояние LS может быть неизвестным либо устаревшим до следующего reconcile → сохраняется семантика снимка приложения, свежая проверка LS запросом CLI не выполняется.
- Старый CLI со старым приложением после обновления → общий бинарь в бандле и явная версия протокола; несовместимость сообщается отдельно от недоступности.

## Migration Plan

Изменение аддитивное: миграция defaults, helper и журнала не требуется. Новый сервер появляется с новым приложением; команда доступна напрямую внутри нового бандла. Пользователь при желании создаёт ссылку в PATH по инструкции. Откат бандла убирает сервер и CLI; оставшаяся ссылка диагностируется оболочкой, старые настройки приложения остаются пригодными.
