# Поддержка remote-групп Little Snitch в списке rule groups

## Why

Скан групп видит только локальные и две встроенные группы; подписанные группы (в терминах Little Snitch — Remote Rule Group, подписка на `.lsrules` по URL) в список не попадают. Парсер `export-model` знает имя только в `userProvidedName` и два встроенных `type`, а у подписки имя лежит в `factoryName` и `type` равен `loadedFromURL` — такая запись молча пропускается как «неизвестный встроенный тип».

Следствие на целевой машине (журнал 2026-09-09): подписку «Require VPN Services» нельзя выбрать во вкладке «Группы», а раз её имя уже вписано в маппинг, каждый reconcile пишет «группа «Require VPN Services» не найдена в Little Snitch» и группа при утечке не закрывается. Пользователь вынужден держать локальную копию «Require VPN Services Local», хотя подписка нужна именно как единый источник правил для нескольких машин.

Факты сняты с целевой машины 2026-09-09 (Little Snitch 6.5): дамп `groups` из `export-model` и проверка `littlesnitch rulegroup -d "Require VPN Services"` — CLI принимает имя подписки как есть, код 0.

## What Changes

- **Парсер модели в helper включает в список подписанные группы**: имя берётся по цепочке полей `userProvidedName` → `customName` → `factoryName` → имя по встроенному `type`; пропускается только запись, у которой имени нет ни в одном виде. Правило «`isActive` отсутствует ⇒ выключена» распространяется на подписки без изменений.
- **Список групп получает вид группы**: встроенная / локальная / подписка. В JSON XPC-ответа появляется необязательное поле `kind`; ответ старого helper без поля читается как раньше.
- **Вкладка «Группы» помечает подписки** подписью «подписка» рядом с состоянием в LS, чтобы одноимённые локальная копия и подписка различались глазами.
- **Одноимённые группы**: в список попадает одна запись, в журнал пишется предупреждение с именем. Различить их на уровне CLI невозможно — `rulegroup -e/-d` принимает только имя.
- **Документация и фикстуры**: README «Формат модели Little Snitch 6» и тестовая модель дополняются записью подписки и новым `type: loadedFromFile` у локальной группы (в июльском снимке этого поля не было).
- Не BREAKING: контракт XPC расширяется необязательным полем, настройки не мигрируют — имена в `leakGroups` остаются идентификатором.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `rule-group-control`: требование «Узкий XPC-контракт» — список групп содержит подписанные группы и вид каждой группы; правило пропуска безымянных записей; терпимость к ответу без поля вида. Требование «Список групп в настройках» — подпись вида у подписок; поведение при одноимённых группах.

## Impact

- `Helper/RuleGroupModelParser.swift`, `RuleGroupInfo` — разбор имени и вида, детерминированный порядок, дубликаты не схлопываются.
- `Helper/HelperProtocol.swift` — описание JSON-ответа `listRuleGroups` с полем `kind`.
- `Domain/RuleGroup.swift` — вид группы в доменной модели (чистый Swift).
- `Application/SyncRuleGroups.swift` — схлопывание одноимённых с предупреждением в журнал.
- `Infrastructure/HelperRuleGroupGateway.swift` — декодирование `kind`.
- `App/Screens/SettingsWindow.swift` (вкладка «Группы») — подпись «подписка».
- Тесты: `Tests/HelperTests/LittleSnitchModelTests.swift`, `RuleGroupModelParserTests.swift`, `Tests/ApplicationTests` (`SyncRuleGroups`, фейк шлюза), `Tests/InfrastructureTests` (декодирование).
- `README.md` §«Формат модели Little Snitch 6», `SPEC.md` §9 (факты о CLI).
- Helper пересобирается ⇒ приложение заметит смену отпечатка и предложит переустановить демон (штатный путь).
