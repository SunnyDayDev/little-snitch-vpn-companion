# Spec Delta

## MODIFIED Requirements

### Requirement: Настраиваемый маппинг состояние → группы

Система SHALL поддерживать у каждого детектора настраиваемый маппинг «состояние → какие rule groups включены», являющийся функцией режима защиты этого детектора:

- **Реактивный режим**: Leak → включить выбранные для детектора группы; Protected → выключить их; Offline, Checking и Paused → детектор не определяет их состояние;
- **Строгий режим**: Protected → выключить группы; все прочие состояния (Leak, Offline, Checking, Paused) → включить группы.

Желания детекторов SHALL сводиться в одну цель арбитражем (см. «Арбитраж групп между детекторами»); применение — только через reconcile по этой цели. Группы вне маппингов всех детекторов SHALL NOT трогаться никогда.

#### Scenario: Применение маппинга при Leak

- **WHEN** детектор перешёл в Leak и в его маппинге выбраны группы
- **THEN** reconcile включает каждую выбранную группу, фактическое состояние которой «выключена»

#### Scenario: Offline не трогает группы в реактивном режиме

- **WHEN** детектор реактивный перешёл в Offline, его группы не входят в другие детекторы
- **THEN** никакие rule groups не включаются и не выключаются

#### Scenario: Offline закрывает в строгом режиме

- **WHEN** детектор строгий перешёл в Offline
- **THEN** reconcile включает каждую группу его маппинга, фактическое состояние которой «выключена»

#### Scenario: Группы другого детектора не трогаются

- **WHEN** детектор A перешёл в Protected, а группа входит только в маппинг детектора B
- **THEN** reconcile после перехода A не меняет состояние этой группы

## ADDED Requirements

### Requirement: Список групп в деталях детектора

Приложение SHALL получать список rule groups (имя + текущее состояние + вид) через helper и отображать его в деталях каждого детектора с чекбоксом «включать этим детектором» у каждой группы. У группы, входящей в маппинг других детекторов, подпись SHALL перечислять их имена («также в …»). Подписанные группы SHALL помечаться подписью «подписка» рядом с состоянием в LS. Список SHALL обновляться при открытии деталей детектора и по кнопке «Обновить список из LS». Если helper вернул несколько групп с одним именем, приложение SHALL показать одну строку и записать в журнал предупреждение с этим именем: различить такие группы при включении по имени невозможно.

#### Scenario: Открытие деталей детектора

- **WHEN** пользователь открывает детали детектора
- **THEN** приложение запрашивает у helper актуальный список групп и отображает его с чекбоксами по маппингу этого детектора

#### Scenario: Группа в нескольких детекторах

- **WHEN** группа входит в маппинг детекторов «Основной» и «Через прокси», и пользователь открыл детали «Через прокси»
- **THEN** строка группы отмечена чекбоксом и несёт подпись «также в «Основной»»

#### Scenario: Подписка в списке

- **WHEN** список содержит группу вида `remote`, включённую в LS
- **THEN** её строка показывает подпись «подписка · включена в LS», а чекбокс работает так же, как у локальной группы

#### Scenario: Одноимённые группы

- **WHEN** список от helper содержит локальную группу и подписку с одинаковым именем
- **THEN** в деталях показана одна строка с этим именем, в журнал записано предупреждение об одноимённых группах, reconcile продолжает работать по имени

#### Scenario: Несуществующее имя группы в маппинге

- **WHEN** reconcile пытается включить группу, имени которой нет в LS
- **THEN** в журнал пишется внятная ошибка с именем детектора, отправляется уведомление, приложение не падает

### Requirement: Арбитраж групп между детекторами

Целевое состояние каждой группы SHALL вычисляться по желаниям всех включённых детекторов, в чьи маппинги она входит; выключенные детекторы в арбитраже SHALL NOT участвовать. Правило:

| Желания детекторов, содержащих группу | Целевое состояние группы |
| --- | --- |
| хотя бы один требует включить | включена (трафик закрыт) |
| никто не требует включить, хотя бы один требует выключить | выключена (трафик открыт) |
| ни один не определяет (реактивные Offline/Checking/Paused) | не трогать |

Reconcile SHALL затрагивать только группы с определённым целевым состоянием. Арбитраж SHALL быть чистой функцией от набора «состояние, режим, группы» включённых детекторов.

#### Scenario: Один закрывает — закрыто

- **WHEN** группа входит в детекторы A (Leak, реактивный) и B (Protected, реактивный)
- **THEN** целевое состояние группы — включена

#### Scenario: Строгий офлайн держит общую группу

- **WHEN** группа входит в детекторы A (Offline, строгий) и B (Protected, строгий)
- **THEN** целевое состояние группы — включена

#### Scenario: Все согласны открыть

- **WHEN** группа входит в детекторы A и B, оба в Protected
- **THEN** целевое состояние группы — выключена

#### Scenario: Один открывает, другой не определяет

- **WHEN** группа входит в детекторы A (Protected, реактивный) и B (Offline, реактивный)
- **THEN** целевое состояние группы — выключена

#### Scenario: Никто не определяет

- **WHEN** группа входит только в реактивные детекторы, все в Offline
- **THEN** группа не трогается: её фактическое состояние остаётся прежним

#### Scenario: Выключенный детектор не участвует

- **WHEN** группа входит в детекторы A (выключен, последний вердикт Leak) и B (Protected)
- **THEN** целевое состояние группы — выключена

### Requirement: Failsafe-конфигурация по объединению строгих детекторов

Failsafe-конфигурация helper SHALL содержать объединение групп всех включённых детекторов в строгом режиме; `strictActive` SHALL быть истинным, когда есть хотя бы один такой детектор и не включён `observeOnly`. Приложение SHALL передавать helper актуальную конфигурацию одной операцией при любом изменении, влияющем на объединение: режим, группы или признак «включён» детектора, добавление и удаление детектора, `observeOnly`. Быстрое безусловное закрытие при засыпании и завершении приложения SHALL включать то же объединение групп. Контракт XPC и формат конфигурации SHALL NOT меняться.

#### Scenario: Два строгих детектора

- **WHEN** включены строгие детекторы с группами «VPN down» и «Telegram» и реактивный детектор с группой «Соцсети»
- **THEN** helper получает конфигурацию со `strictActive=true` и группами «VPN down», «Telegram»

#### Scenario: Последний строгий детектор выключен

- **WHEN** пользователь выключает единственный строгий детектор
- **THEN** helper получает конфигурацию со `strictActive=false`, dead-man's switch и закрытие на загрузке выключены

#### Scenario: Закрытие при завершении по объединению

- **WHEN** приложение завершается при двух строгих детекторах
- **THEN** включаются группы обоих детекторов без листинга, как при одном детекторе

## REMOVED Requirements

### Requirement: Список групп в настройках

**Reason**: Вкладка «Группы» удалена: группы выбираются в деталях каждого детектора, у группы, входящей в другие детекторы, это подписано.
**Migration**: Выбор групп выполняется в деталях детектора («Настройки → Детекторы → детектор → Группы»); существующий маппинг переносится миграцией в детектор «Основной». См. «Список групп в деталях детектора».
