# Несколько детекторов: свои правила, прокси и группы у каждого

## Why

Сейчас в приложении ровно один детектор: одна цепочка, один набор критериев, один список групп. На практике часть приложений ходит другим путём — через прокси с резидентным выходом, — и за этим путём нужно следить отдельно: у него свои ожидаемые адреса, `warp=on` для него не признак защиты, а при утечке закрывать надо только его группы. Один детектор этого не умеет: проба идёт системным маршрутом и второй путь не видит, а маппинг «состояние → группы» один на всех.

## What Changes

- **Детектор становится сущностью** с именем, тумблером «включён», собственным режимом защиты, маяком, прокси, критериями классификации и списком групп. Детекторов может быть сколько угодно; каждый ведёт свою машину состояний и свои растяжку и пробы. Слои, описывающие машину, а не путь, — события сетевого пути, события питания и РУ-маяк с прямым IP сети — остаются общими и раздаются всем детекторам.
- **Проба и растяжка детектора ходят через прокси**: HTTP CONNECT или SOCKS5, хост и порт, без аутентификации в этой версии. Растяжка на детектор опциональна.
- **Маяк на детектор** с двумя форматами ответа: `cdn-cgi/trace` (его отдаёт любой домен за Cloudflare) и голый IP либо JSON-строка с IP. У маяка без поля `warp=` защиту определяют только ожидаемые адреса.
- **Критерий защиты**: `warp=on` становится тумблером детектора «warp=on считается защитой» (по умолчанию включён, как сейчас). Ожидаемые и запрещённые IP — у каждого детектора свои; прямой IP сети от РУ-маяка общий и попадает в запрещённые всех детекторов. Любой неожиданный egress по-прежнему утечка.
- **Арбитраж групп между детекторами.** Группа включена (трафик закрыт), пока хоть один детектор требует её включить; выключена (трафик открыт), только когда все детекторы, в которые она входит, требуют выключить; не трогается, когда ни один детектор не определяет её целевое состояние. Reconcile один на всех, считает объединённую цель.
- **Режим защиты на детектор.** Пауза, тумблер «Мониторинг» и `observeOnly` остаются общими. Выключение или удаление детектора открывает его группы, если их не держит другой детектор, — по аналогии с переходом «строгий → реактивный».
- **Failsafe helper** получает объединение групп строгих включённых детекторов; `strictActive` взводится, когда есть хоть один такой детектор. Контракт XPC и формат `FailsafeConfig` не меняются.
- **Эскалация** остаётся общей: любой детектор в Leak при недоступном helper выключает Wi-Fi.
- **UI настроек**: вкладка «Детектор» становится вкладкой «Детекторы» — список с переходом в детали; общие интервалы, прямой IP и РУ-маяк живут под списком. Вкладка «Группы» удаляется: группы выбираются в деталях детектора, и у группы, входящей в другие детекторы, это подписано. Карточка «Режим защиты» переезжает из «Общих» в детали детектора.
- **Поповер и иконка**: заголовок и иконка показывают худшее состояние среди включённых детекторов; между баннером и инфо-строками появляется блок детекторов с состоянием и egress каждого.
- **Уведомления и журнал** несут имя детектора.
- **Миграция.** Существующие `expectedIPs`, `forbiddenEgressIPs`, `leakGroups` и `protectionMode` при первом запуске новой версии превращаются в детектор «Основной» без прокси; поведение существующих пользователей не меняется. **BREAKING**: эти четыре ключа `defaults` перестают быть источником правды после миграции — скрипты, правившие их через `defaults write`, должны править массив детекторов. Скрытые debug-рычаги `debugIgnoreWarp` и `debugFakeEgressIP` остаются глобальными и действуют на все детекторы.

## Capabilities

### New Capabilities

Нет: детектор, арбитраж и прокси ложатся в существующие capability по функциональным областям.

### Modified Capabilities

- `egress-detection`: классификация становится функцией правил детектора (тумблер `warp=on`, свои ожидаемые и запрещённые IP, общий прямой IP); маяк и формат ответа на детектор; проба и растяжка через прокси; растяжка опциональна; общие слои раздаются всем детекторам; guard РУ-маяка сверяется с защищёнными ответами всех детекторов.
- `state-machine`: машина состояний на детектор с собственным режимом; пауза и тумблер мониторинга общие; инвариант строгого режима переформулирован через арбитраж; переключение режима и выключение детектора — переходные reconcile по объединённой цели.
- `rule-group-control`: маппинг «состояние → группы» на детектор; новое требование об арбитраже групп между детекторами; failsafe-конфигурация из объединения групп строгих детекторов; список групп переезжает в детали детектора.
- `app-settings`: хранение массива детекторов и миграция старых ключей в детектор «Основной»; две вкладки вместо трёх; список детекторов и экран деталей; карточка режима защиты в деталях детектора; общие интервалы и РУ-маяк под списком.
- `menu-bar-ui`: иконка по худшему состоянию среди включённых детекторов; блок детекторов в поповере; заголовок и баннер называют детектор.
- `user-notifications`: тексты уведомлений называют детектор.
- `event-journal`: запись журнала получает поле «детектор».
- `failsafe-escalation`: эскалация по любому детектору в Leak; `observeOnly` и границы эскалации действуют на все детекторы.

## Impact

- **Domain**: `DetectorConfig` и `DetectorID`; `EgressCriteria` получает тумблер `warp=on`; `BeaconFormat` и разбор голого IP переезжают из РУ-маяка в домен; `RuleGroupMapping` и `LeakPolicy.targetEnabledGroups` считаются на детектор; новый чистый `GroupArbiter` сводит желания детекторов в одну цель; `StateMachine` без изменений, но экземпляров N. Таблицы арбитража и классификации покрываются построчно.
- **Application**: `AppSettings.detectors` вместо четырёх плоских полей; `MonitoringCoordinator` держит набор детекторных рантаймов (машина, растяжка, цикл проб, поколения проб) и общие слои; `ApplyPolicy` применяет объединённую цель; `forceEnable` на сон и выход — по объединению групп строгих детекторов; `FailsafeConfig` собирается из того же объединения; `DirectIPGuard` получает ответы всех детекторов.
- **Infrastructure**: `CloudflareBeaconProber` становится пробером с URL, форматом и прокси детектора через `URLSessionConfiguration.proxyConfigurations`; `TripwireConnection` принимает хост маяка и прокси через `NWParameters`; `DefaultsSettingsStore` хранит массив детекторов одним ключом и мигрирует старые. `ProxyConfiguration` доступна с macOS 14 — внутри порога 15.7, гейт не нужен.
- **App**: `SettingsWindow` (вкладка «Детекторы», экран деталей, удаление вкладки «Группы»), `MenuBarPopover` и `DSStatusIcon` (худшее состояние, блок детекторов), `AppModel` (CRUD детекторов, переходные reconcile при выключении и удалении), новая молекула «Ряд детектора» в дизайн-системе.
- **Helper**: без изменений кода; `FailsafeConfig.groups` получает объединение.
- **Тесты**: таблицы `GroupArbiter` и классификации по правилам детектора; координатор с двумя детекторами (утечка одного при защите другого, общая группа, выключение детектора, миграция настроек).
- **Документы и макеты**: `design/app.pen` (вкладка «Детекторы», детали, поповеры с блоком детекторов, light и dark; удаление вкладок «Детектор» и «Группы»), README (настройка под себя, debug-рычаги), SPEC.md §4, §5, §7, §13 как справочник.
