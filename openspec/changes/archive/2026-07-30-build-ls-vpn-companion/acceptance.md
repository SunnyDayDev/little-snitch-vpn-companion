# Чеклист приёмки (§14 SPEC.md)

Все 16 сценариев требуют действий, которые нельзя выполнить за пользователя: одобрение
helper в Системных настройках (пароль), включение и выключение VPN-клиента, отключение
Wi-Fi, перезагрузка, сон/пробуждение. Ниже — порядок прогона и что именно считать
успехом. Отмечать `[x]` по мере прохождения.

## Подготовка

- [x] П1. Создать самоподписанный сертификат и переключить `Signing.xcconfig`
      (см. README → «Подпись»). Сделано 2026-07-30: сертификат
      `little-snitch-vpn-companion`, оба таргета подписаны им, Hardened Runtime активен,
      строгий XPC-requirement проверен (приложение удовлетворяет, посторонние — нет).
      Попутно найдено и исправлено: с настоящим сертификатом обязателен
      `ENABLE_DEBUG_DYLIB = NO`, иначе library validation роняет приложение при запуске.
- [x] П2. Собрать и запустить приложение (README → «Сборка и запуск»).
      Проверено: приложение поднимается, стартовая проба даёт Protected, журнал пишется.
- [x] П3. Онбординг, шаг 1: «Установить helper…» → одобрить в **System Settings →
      Основные → Объекты входа**. Успех: в поповере строка «Helper» исчезает
      (недоступности больше нет), во вкладке «Группы» внизу — «helper подключён · root».
- [x] П3.1. Если приложение пересобиралось после установки helper — нажать
      **Настройки → Общие → «Переустановить…»** и одобрить объект входа заново.
      `SMAppService` привязывает демон к подписи приложения: новая сборка ломает
      запуск (`launchctl` показывает `EX_CONFIG`). Для обычной установки шаг не нужен.
      Если не помогло (`job state = spawn failed`, `needs LWCR update`) — снять
      застрявшую запись launchd и дать приложению зарегистрировать демон заново:
      `sudo launchctl bootout system/dev.sunnyday.lsvpncompanion.helper`
- [x] П3.5. Разрешить доступ CLI в **Little Snitch → Настройки → Безопасность**.
      Без этого `littlesnitch` даже под root отвечает `command line tool is not
      authorized to make changes`, и список групп не читается. Приложение показывает
      эту причину отдельной строкой с кнопкой «Открыть Little Snitch…».
- [x] П4. Онбординг, шаг 2: создать в Little Snitch rule group **«VPN down»** с
      deny-правилами для Claude, всех JetBrains IDE и Android Studio.
      Вместо новой группы используется существующая «Require VPN Services».
      Пользователь подтвердил 2026-07-30, что её правила закрывают нужные
      приложения, — инвариант §1 ТЗ соблюдён.
- [x] П4.5. Список групп читается из LS. Проверено 2026-07-30: приложение показывает
      `iCloud Services`, `macOS Services`, `Require VPN Services` — имена и состояния
      берутся из модели LS (см. README → «Формат модели Little Snitch 6»).
- [x] П5. Настройки → Группы → «Обновить список из LS»: группа появилась в таблице,
      чекбокс «включать при утечке» у неё установлен (или установить вручную).
      Выполнено 2026-07-30 на существующей группе «Require VPN Services» — вместо
      создания «VPN down» (см. П4).
- [x] П6. Онбординг, шаг 3: разрешить уведомления.
      Проверено 2026-07-30: разрешение теперь запрашивается и при обычном запуске —
      онбординг можно закрыть, не нажав шаг 3, и уведомления молча не работали бы.
      Итог пишется в журнал («уведомления разрешены»), а отказ доставки — отдельной
      ошибкой; в настройках при отсутствии разрешения появляется строка с кнопкой.
- [x] П7. Включить режим наблюдения (Настройки → Общие → «Режим наблюдения») на время
      первых прогонов, если не хочется реальных блокировок; для сценариев 2, 5, 8, 9, 13, 14
      его нужно выключить. Проверено пользователем 2026-07-30.

## Сценарии

- [x] 1. Машина в защищённой сети (`warp=on`) → Protected, группы выключены, уведомлений нет.
      Проверено 2026-07-30: за час работы ни одного действия с группами.
- [x] 2. `defaults write dev.sunnyday.lsvpncompanion debugIgnoreWarp -bool true` →
      за ≤5 с Leak, группа включена, уведомление; запрещённые приложения без сети,
      браузер работает.
      Проверено 2026-07-30 на группе «Require VPN Services»: 08:01:25 переход
      Protected → Leak по триггеру `confirmation` (то есть после подтверждающей
      пробы, §4.3), группа включена тем же действием.
      **Важно про время:** debug-рычаг — не сетевое событие, он подхватывается
      следующей пробой, поэтому от `defaults write` до Leak проходит до
      `probeSeconds` (60 с). «≤5 с» из ТЗ относится к реальному отвалу VPN — его
      ловят растяжка и события пути за 1–2 с (сценарии 5–6).
- [x] 3. `defaults delete dev.sunnyday.lsvpncompanion debugIgnoreWarp` → Protected,
      группа выключилась сама, уведомление о восстановлении.
      Проверено 2026-07-30: 08:02:46 переход Leak → Protected по плановой пробе,
      группа выключена автоматически. Восстановление тоже ограничено интервалом
      плановой пробы.
- [x] 4. Выключить Wi-Fi → Offline, группы не тронуты (проверить в LS и в журнале:
      записей «действие» нет). Подтверждено пользователем 2026-07-30.
- [x] 5. Полевой: чужая сеть без VPN → Leak, группы включены, обычные приложения работают.
      Подтверждено пользователем 2026-07-30.
- [x] 6. Там же включить VPN-клиент Happ → Protected, блок снят автоматически.
      Подтверждено пользователем 2026-07-30. Вместе со сценарием 5 это проверка
      реальной скорости реакции (растяжка и события пути), а не debug-рычага.
- [ ] 7. Перезагрузка → приложение и helper поднялись сами, reconcile отработал
      (в журнале первая запись — переход по стартовой пробе).
      Предусловие выполнено 2026-07-30: приложение установлено в
      `~/Applications` (`Scripts/install.sh`), автозапуск и регистрация демона
      теперь ссылаются на постоянный путь, а не на каталог сборки.
- [x] 8. Выгрузить или сломать helper при Leak (например,
      `sudo launchctl bootout system/dev.sunnyday.lsvpncompanion.helper`) → эскалация:
      Wi-Fi выключен + уведомление с объяснением.
- [x] 9. Пауза → вызвать утечку (сценарий 2) → Возобновить: в паузе действий нет,
      после возобновления Leak и группы включены.
      Подтверждено пользователем 2026-07-30, включая паузу во время утечки.
- [ ] 10. Сон → пробуждение со сменой сети → растяжка переустановилась, проба ушла по
      событию пути (в журнале записи «путь» и свежая проба).
- [x] 11. `rulegroup -e` уже включённой группы: включить группу вручную в LS при Leak,
      дождаться следующего reconcile → ошибки нет, лишних операций нет (идемпотентность).
      Проверено 2026-07-30: после «группа выключена» в 08:02:46 пробы шли каждую
      минуту, повторных операций с группой в журнале нет.
- [x] 12. Вписать в маппинг несуществующее имя группы (Настройки → Группы, снять и
      поставить чекбокс после переименования группы в LS) → внятная ошибка в журнале
      и уведомление, приложение не падает.
- [x] 13. `defaults write dev.sunnyday.lsvpncompanion debugFakeEgressIP -string "198.51.100.10"`
      → Leak с диагнозом «цепочка вышла напрямую с сервера 198.51.100.10», группы включены
      (даже при `warp=on`).
      Проверено 2026-07-30: 08:18:49 Leak по подтверждающей пробе, egress
      `198.51.100.10`, группа включена; 08:20:50 после снятия рычага — Protected и
      группа выключена. Подмена отдаёт `warp=on`, то есть denylist действительно
      сильнее признака WARP (§4.1).
- [x] 14. `defaults write dev.sunnyday.lsvpncompanion debugFakeEgressIP -string "<текущий прямой РУ-IP из Настройки → Детектор>"`
      → Leak с диагнозом «полный обход VPN».
      Проверено 2026-07-30 на `192.0.2.10`: 08:22:57 Leak, в журнале
      «диагноз: полный обход VPN: трафик идёт с прямого IP сети»; 08:23:58 —
      Protected, группа выключена. Диагноз теперь пишется в журнал отдельной
      записью, а не только в уведомление.
- [x] 15. РУ-маяк вернул IP, равный текущему protected-egress (воспроизводится, если
      выключить РУ-сплит на стороне VPN) → запись в denylist НЕ добавлена, в журнале
      предупреждение «РУ-маяк прошёл через VPN, сплит не работает?».
      Подтверждено пользователем 2026-07-30. Это тот самый вырожденный случай,
      из-за которого guard раньше отравлял denylist собственным egress.
- [x] 16. РУ-маяк недоступен (например, `ruBeaconURL` и `ruBeaconFallbackURL` временно
      указать на несуществующий `.ru`-домен) → состояния не меняются, в Настройки →
      Детектор давность прямого IP растёт.
      Прогнано 2026-07-30 (оба адреса — на несуществующие `.ru`-домены, 100 с):
      ни одной записи об обновлении прямого IP, состояние из-за этого не менялось,
      ошибок нет — сбой РУ-маяка некритичен (§4.4). Адреса восстановлены автоматически.
      Рост давности в UI глазами не проверялся — журнал показывает отсутствие
      обновлений, что то же самое.

Не забыть снять debug-рычаги после прогона:

```bash
defaults delete dev.sunnyday.lsvpncompanion debugIgnoreWarp; defaults delete dev.sunnyday.lsvpncompanion debugFakeEgressIP
```

## Обкатка (задача 8.3)

- [–] О1. Сутки в `observeOnly`: раз в несколько часов смотреть журнал на ложные
      срабатывания (переходы в Leak без реальной причины). Ожидание: переходов нет либо
      они совпадают с фактическими отвалами VPN.
      **Пропущено по решению пользователя 2026-07-30**: обкатка идёт сразу в боевом
      режиме. Риск принят — ложное срабатывание блокирует запрещённые приложения до
      следующей пробы (≤60 с). Журнал остаётся источником правды: фильтр «Переходы»
      в окне журнала показывает все переходы в Leak с их диагнозом.
- [x] О2. Выключить `observeOnly` — боевой режим. Пользователь переходит к
      эксплуатации 2026-07-30.
