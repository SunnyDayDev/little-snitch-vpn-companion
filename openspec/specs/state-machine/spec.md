# state-machine

## Purpose

Доменное ядро приложения: состояния защищённости (Protected/Leak/Offline/Paused), таблица переходов между ними по результатам проб и действиям пользователя, флаг «helper недоступен» и принцип идемпотентного reconcile.

## Requirements

### Requirement: Множество состояний

Доменная модель SHALL определять состояния `Protected`, `Leak`, `Offline`, `Paused` и отдельный (ортогональный состоянию) флаг «helper недоступен».

#### Scenario: Флаг helper недоступен не меняет состояние

- **WHEN** вызов helper завершился ошибкой при текущем состоянии Leak
- **THEN** состояние остаётся Leak, взводится флаг «helper недоступен»

### Requirement: Таблица переходов

State machine SHALL реализовывать переходы:

| Из | Событие | В | Действия |
|---|---|---|---|
| любое (кроме Paused) | проба ×2 = чужой egress | Leak | reconcile: включить группы по маппингу; уведомление |
| Leak | проба = защищён | Protected | reconcile: выключить группы; уведомление |
| Protected | обрыв растяжки / событие пути | — | немедленная проба → переход по результату |
| Protected/Leak | пробы не отвечают | Offline | группы НЕ трогать |
| Offline | проба ответила | Protected или Leak | по результату + reconcile |
| любое | пользователь: Пауза | Paused | группы НЕ трогать; детектор остановить |
| Paused | пользователь: Возобновить | по пробе | немедленная проба + reconcile |
| Leak | helper не отвечает | Leak | эскалация, если включена |
| старт приложения | — | по пробе | немедленная проба + reconcile |

#### Scenario: Подтверждённая утечка из Protected

- **WHEN** состояние Protected и две пробы подряд дали чужой egress
- **THEN** состояние становится Leak, выполняется reconcile (включить группы маппинга) и отправляется уведомление

#### Scenario: Восстановление из Leak

- **WHEN** состояние Leak и проба дала protected
- **THEN** состояние становится Protected, выполняется reconcile (выключить группы) и отправляется уведомление

#### Scenario: Пробы перестали отвечать

- **WHEN** состояние Protected или Leak и пробы не отвечают (offline-результаты)
- **THEN** состояние становится Offline, группы LS не изменяются

#### Scenario: Сеть вернулась из Offline

- **WHEN** состояние Offline и проба ответила
- **THEN** состояние становится Protected или Leak по результату пробы и выполняется reconcile

#### Scenario: Пауза пользователем

- **WHEN** пользователь ставит мониторинг на паузу из любого состояния
- **THEN** состояние становится Paused, детектор останавливается, группы LS не изменяются

#### Scenario: Возобновление после паузы

- **WHEN** пользователь возобновляет мониторинг из Paused
- **THEN** немедленно выполняется проба, состояние устанавливается по её результату, выполняется reconcile

#### Scenario: В паузе утечка игнорируется

- **WHEN** состояние Paused и egress фактически чужой
- **THEN** никакие пробы не выполняются, переходов и действий с группами нет

#### Scenario: Старт приложения

- **WHEN** приложение стартует
- **THEN** выполняется немедленная проба, состояние устанавливается по результату и выполняется reconcile

### Requirement: Reconcile вместо истории

При каждом переходе состояний и на старте система SHALL сверять фактическое состояние rule groups Little Snitch с целевым для текущего состояния и приводить к нему (reconcile). Система SHALL NOT полагаться на память о ранее выполненных включениях/выключениях. Повторное включение уже включённой группы — допустимая no-op операция.

#### Scenario: Reconcile на старте при рассинхроне

- **WHEN** приложение стартует в Protected, а группа маппинга фактически включена в LS (осталась с прошлого раза)
- **THEN** reconcile выключает группу

#### Scenario: Идемпотентность reconcile

- **WHEN** reconcile требует включить группу, которая уже включена
- **THEN** операция выполняется без ошибки и не меняет наблюдаемое состояние

### Requirement: Ошибка применения не меняет состояние детектора

Все действия SHALL быть идемпотентны; ошибка применения политики (недоступный helper, ошибка CLI) SHALL NOT менять состояние детектора, но SHALL отображаться (уведомление + журнал) и взводить флаг «helper недоступен».

#### Scenario: Ошибка reconcile при переходе в Leak

- **WHEN** переход в Leak требует включить группы, а helper возвращает ошибку
- **THEN** состояние остаётся Leak, взводится флаг «helper недоступен», пишется журнал и отправляется уведомление об ошибке
